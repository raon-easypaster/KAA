생성형 AI와 AI 에이전트

같은 AI라도 하는 일이 다릅니다. 두 가지를 도서관의 사서와 일을 맡기는 비서로 이해합니다.

생성형 AI

📚 도서관 사서

“이 주제에 맞는 책을 알려주세요” 하면 설명해 주고 콘텐츠를 만들어 줍니다. 질문하면 답은 주지만, 답을 받아 다음 작업으로 옮기는 건 나입니다.

예) 공과 질문 10개 만들어 줘 · 요한복음 3장을 저학년 눈높이로 설명해 줘

🗂 일을 맡기는 비서

STEP 2 · 강의와 시연

생성형 AI와 에이전트의 차이

생성형 AI는 ‘말’을 하고, 에이전트는 ‘일’을 합니다. 단, 에이전트도 방향은 사람이 정해야 합니다.

구분생성형 AIAI 에이전트
하는 일요청에 답을 만들어 줌목표를 끝까지 수행함
움직임한 번 묻고 한 번 답함계획 → 실행 → 확인 → 수정을 반복
도구 사용주로 글로 답함파일 만들기, 웹 검색, 코드 실행 등 직접 사용
결과물복사해서 내가 붙여 넣어야 함완성된 파일·폴더가 만들어짐
비유도서관 사서일을 맡기는 비서
시연 · 같은 요청, 두 가지 결과

① 채팅 AI에 “초등부 소개 페이지 만들어 줘” → 코드 글이 나오고, 사람이 붙여 넣어야 함.
② 에이전트에게 같은 요청 → 폴더에 파일이 생기고 브라우저에서 바로 열림.

STEP 3 · 시연과 나눔

예시 홈페이지와 부서별 나눔

라온동행교회 홈페이지를 함께 보고, 우리 부서에는 어떤 페이지가 필요한지 이야기합니다.

EXAMPLE라온동행교회 · raondonghaeng.org예배안내 / 처음 오셨나요? / 우리교회 / 이번 주 말씀 / 교회소식 / 주보 / 사진첩 / 오시는 길

보면서 이야기해 볼 점

  • 처음 온 사람이 가장 궁금해할 것(시간, 장소, 안내)을 맨 앞에 두었습니다.
  • 말씀 쇼츠 등 짧은 영상으로 부담 없이 접근합니다.
  • 사진첩과 소식으로 살아 있는 공동체임을 보여 줍니다.
  • 지금 사이트에는 부서 전용 페이지가 없습니다. “우리 부서는 이런 페이지를 따로 만들 수 있다면?”

부서별 나눔 · 공통 질문 5가지

  • 어떤 아이들이 모이나요? (나이, 인원, 분위기)
  • 부모님은 무엇을 가장 궁금해하나요? (시간, 장소, 준비물, 행사)
  • 아이들이 집에서도 하고 싶어 할 것은? (퀴즈, 암송, 색칠, 영상)
  • 이번 달 꼭 알려야 할 것은?
  • 사진·이름은 어디까지 공개해도 되나요? (초상권·개인정보)

부서별 아이디어 예시

부서소개아이들이 함께할 수 있는 코너
영유아·유치부부모님과 함께 보는 페이지노래·율동 영상, 오늘 배운 말씀 그림, 부모 안내
유초등부활동 중심말씀 퀴즈, 암송 도전 체크, 오늘의 공과 요약, 갤러리
소년부(고학년)도전·성장성경 인물 카드, 퀴즈 랭킹, 감사 나눔 게시판
중고등부자기 표현묵상 한 줄 나눔, 행사 신청, 찬양 플레이리스트
청년부공동체 소개모임 안내, 소그룹 신청, 간증
자료 모으기

사진(동의받은 것만), 행사 일정, 공과 주제, 소개 문장, 교사 공용 연락처, 좋아하는 노래·영상 링크를 폴더 하나에 모읍니다. 수업 전에 준비하면 좋고, 못 했어도 수업 중에 함께 모읍니다.

어려운 용어는 식당으로 풀면 쉽습니다. 손님이 보는 홀과, 보이지 않는 주방.

용어식당 비유홈페이지에서는
프론트엔드손님이 보는 홀·메뉴판·인테리어화면, 글자, 색, 버튼, 사진
백엔드손님이 못 보는 주방·창고·장부데이터 저장, 로그인, 퀴즈 점수 기록, 게시글 저장
데이터베이스주방의 재료 창고, 주문 장부아이들 이름, 점수, 글을 보관하는 곳
배포(호스팅)가게 문을 여는 것인터넷 주소로 누구나 접속하게 하기

STEP 5 · 강의와 활동

사람이 할 일, AI가 할 일

역할을 나누면 일이 쉬워집니다. 방향과 책임은 사람이, 수고와 반복은 AI가.

구분사람(교사)AI 에이전트
기획왜 만드는지, 누구를 위한 것인지 정하기화면 코드 작성, 파일 구성
내용아이들 눈높이와 신앙적 내용의 옳고 그름 판단문구 초안, 퀴즈 후보, 디자인 시안
개인정보사진·이름 공개 허락과 결정오류 찾기와 수정 반복
검토성경 내용 검토 (AI는 틀릴 수 있음)여러 버전을 빠르게 만들어 비교용 제공
결정최종 승인, 공개 여부 결정수정 요청 즉시 반영
돌봄아이들과 부모와의 관계와 돌봄대신할 수 없음
활동 · 사람? AI?

포스트잇에 부서 홈페이지 일을 하나씩 적고(공과 요약 쓰기, 사진 공개 결정, 버튼 색 정하기), ‘사람’과 ‘AI’ 두 칸으로 나눠 붙입니다. 헷갈리는 것은 함께 이야기합니다.

꼭 지킬 안전 원칙
  • 아이 얼굴·실명·연락처는 부모 동의 없이 올리지 않습니다.
  • AI가 쓴 성경·교리 설명은 반드시 교사가 확인합니다.
  • 비밀번호·API 키는 AI 채팅창에 붙여 넣지 않습니다.

STEP 6 · 팀 활동 · PRD 실습

PRD 작성 도우미로
부서 설계도 만들기

빈 화면에서 설계도를 혼자 쓰는 건 어렵습니다. ‘PRD 작성 도우미’가 질문을 던지면, 답만 하세요. PRD가 완성됩니다. 완성한 PRD는 그대로 AI 에이전트에게 넘겨 홈페이지를 만듭니다(STEP 7).

PRD란 무엇인가

PRD(Product Requirements Document)는 어려운 게 아니라 “뭘 만들지 미리 적어둔 설계도”입니다. AI 에이전트에게 주는 업무 지시서이기도 합니다.

1 · 왜 만드는가

개요, 목표 — 우리 부서 홈페이지가 필요한 이유

2 · 누가 쓰는가

아이, 부모, 교사. 기능과 디자인의 기준이 됩니다

3 · 무엇을 만드는가

꼭 들어갈 기능과 화면 구성

4 · 어떻게 사용하는가

아이가 폰으로 열어 퀴즈를 푸는 것 같은 사용 장면

5 · 무엇으로 만드는가

기술 스택. 처음에는 AI 추천을 받아도 됩니다

가장 중요한 항목은 ‘하지 않을 것’이다

범위를 정해 두지 않으면 AI가 이것저것 과하게 만들어 오히려 복잡해집니다. ‘이번엔 이건 안 만든다’를 적는 것이 PRD에서 가장 중요합니다. 교회학교에서는 아이들의 실명, 얼굴 사진, 연락처, 글 남기기가 대표적입니다.

# PRD 작성 도우미 (교회학교 부서 홈페이지)
## 목적 및 역할
- 교회학교 교사가 우리 부서 홈페이지의 PRD(제품 요구사항 정의서)를 체계적으로 작성하도록 돕는, 친절하고 분석적인 IT 기획자(PM) 역할을 한다.
- 사용자의 아이디어를 구조화해서, 코딩 에이전트가 바로 이해하고 만들 수 있는 명세서로 정리한다.
- 사용자는 코딩을 전혀 모른다. 쉬운 말로 설명한다.
## 행동 지침 및 규칙
### 1) 초기 인사 (필수)
사용자가 대화를 시작하면 다른 설명 없이 가장 먼저 아래 문구로 인사한다.
> 안녕하세요! 우리 부서 홈페이지의 PRD를 단계별로 도와드리겠습니다. 먼저, 어느 부서의 홈페이지인지, 홈페이지 이름을 알려주세요. (정하지 않으셨다면 '가칭'이나 '미정'이라고 적어주셔도 좋습니다.)
### 2) 점진적 정보 수집
- 사용자가 이미 말한 내용은 다시 묻지 않고, 그 내용으로 채워 나간다.
- 총 8단계를 차례로 진행하고, 한 번에 하나씩만 묻는다.
  1. 프로젝트 개요 (부서, 만드는 이유)
  2. 사용자 시나리오 (아이, 부모, 교사가 각각 무엇을 하는지)
  3. 핵심 기능 (꼭 필요한 것 3~5개)
  4. 기술 스택 (모르면 추천)
  5. 화면 구성 (어떤 페이지가 필요한지)
  6. 상세 기능 명세 (페이지마다 무엇이 들어가는지)
  7. 디자인 가이드 (색, 분위기, 글씨 크기, 모바일)
  8. 제약 사항 (이번에 만들지 않을 것)
- 매 단계 답변을 짧게 요약하고 다음으로 넘어간다.
### 3) 사용자 지원
- 답이 모호하거나 '잘 모르겠다'고 하면 부서의 성격에 맞는 선택지 2~4개를 제시해서 고르기 쉽게 돕는다.
- 전문 용어는 피하고, 필요하면 쉬운 말로 풀어 설명한다.
- 범위가 너무 넓어지면 꼭 필요한 것부터(MVP)로 좁히도록 안내한다.
### 4) 교회학교 안전 원칙 (반드시 지킬 것)
- 아이들의 실명, 얼굴 사진, 연락처, 주소는 홈페이지에 넣지 않는 쪽으로 안내한다.
- 아이들이 글을 남기거나 점수를 저장하는 기능(로그인, 게시판)은 처음에는 넣지 않는 쪽으로 권한다.
- 성경과 교리 내용은 교사가 확인해야 한다고 PRD에 명시한다.
### 5) 최종 결과물
- 정보 수집이 끝나거나 사용자가 요청하면, AI 코딩 에이전트(Antigravity, Claude Code, Codex 등)가 읽을 PRD를 .md 파일로 제공한다. 파일이 어려우면 전체를 하나의 코드 블록에 담는다.
- 파일 맨 위에 코딩 에이전트에게 보내는 요청문을 넣는다. (코드를 쓰기 전에 계획부터 보여 달라는 내용)
- 문서 구조: 프로젝트 개요 / 기술 스택 / 개발 작업 목록(우선순위 표시) / 화면별 상세 명세 / 이번에 만들지 않을 것
## 말투
- 차분하고 친절하게, 사용자가 위축되지 않도록 지지적인 태도를 유지한다.
강사가 짚어줄 것
  • 이 지침이 하는 일을 한 문장으로: “AI에게 직무기술서를 준 것”입니다. 역할, 무엇을 묻고, 어떤 순서로, 어떤 말투로, 마지막에 무엇을 내놓을지가 적혀 있습니다.
  • 내용을 이해할 필요는 없습니다. 통째로 붙여넣기만 하면 됩니다. “이렇게 적어 두면 AI가 그 역할을 계속 유지한다”는 원리만 알려 주세요.
  • 4번 ‘교회학교 안전 원칙’은 아이들을 지키기 위한 부분이라 꼭 읽고 넘어갑니다.

## 1. 개요
- 만드는 이유(한 문장):
- 누가 쓰는가: 아이 / 부모 / 교사
- 아이들의 나이와 특징:
- 홈페이지 분위기(색, 느낌):

## 2. 꼭 들어갈 페이지(3~5개)
- 부서 소개
- 이번 달 일정 / 공지
- 오늘의 말씀과 공과 요약
- 아이들 코너(퀴즈, 암송 등)
- 사진 갤러리(동의받은 사진만)

## 3. 아이들이 할 수 있는 것(1~2개)
-

## 4. 이번에 만들지 않을 것
- 개인정보, 실명, 연락처, 로그인, 글 남기기

## 5. 준비한 자료
- 사진, 문서, 영상 링크

## 6. 기술 조건
- 간단한 정적 웹사이트(HTML/CSS), 한국어, 모바일 반응형

- 예: 아이가 폰으로 열어 퀴즈를 풀 수 있다

  1. 부서별 4~6명이 모입니다. 역할: 진행자 · 기록자 · 자료 담당 · 발표자

마무리 체크리스트

  • PRD 작성 도우미를 세팅했다 (AI Studio 또는 Gem)

간단한 정적 웹사이트(HTML/CSS)로 만들 거야.
1단계가 이 실습의 핵심이다

“계획이 마음에 안 들면 ‘퀴즈 페이지를 빼줘’, ‘일정을 먼저 만들어줘’처럼 계획 단계에서 고치세요. 집을 다 지은 뒤 벽을 옮기는 것보다 도면에서 옮기는 게 훨씬 쉽습니다.”

STEP 7-2

홈페이지 생성

가장 작은 버전부터 만듭니다. 에이전트가 파일을 만드는 과정을 함께 지켜봅니다.

2단계 프롬프트
계획이 좋아. 이 계획대로 우리 부서 홈페이지를 만들어줘.

- 간단한 정적 웹사이트(HTML/CSS)로 만들어줘.
- 전부 한국어로, 스마트폰에서도 잘 보이게 반응형으로 만들어줘.
- 아직 실제 사진이 없으니, 자리표시용(placeholder) 이미지를 넣어줘.
- 다 만든 뒤에는 브라우저에서 어떻게 보이는지 미리보기로 보여줘.
STEP 7-3

우리 부서 정보 채우기

3단계 프롬프트
우리 부서 실제 정보를 반영해줘.
- 부서 이름: [부서 이름]
- 소개 문장 / 표어: [한두 문장]
- 모임 시간과 장소: [예: 주일 오전 11시, 본당 2층]
- 이번 달 일정: [날짜와 행사]
- 오늘의 공과 요약: [제목과 핵심 말씀]
- 영상: 교회 공식 채널 영상 링크 [주소]
3단계 주의사항
  • 아이·교인의 개인정보는 올리지 않습니다. 교사 공용 연락처만 사용합니다.
STEP 7-4

디자인과 모바일 화면 다듬기

4단계 프롬프트
디자인과 모바일 화면을 다듬어줘.
- 색상: 우리 부서 느낌의 밝은 [색] 계열, 강조색은 하나만
- 모바일에서는 햄버거 메뉴와 누르기 편한 큰 버튼
- 상단에 모임 시간과 오시는 길 바로가기 버튼을 크게
- 글씨는 아이들이 읽기 편하게 크게
4단계 주의사항
  • PC와 폰 화면을 둘 다 열어 레이아웃이 깨지지 않는지 확인합니다.
STEP 7-5

아이들 코너와 안내 추가

5단계 프롬프트
아이들 코너와 안내를 추가해줘.
- 오늘의 말씀 퀴즈 3문제(정답을 누르면 바로 알려주는 방식, 저장 없이 화면에서만 동작)
- 암송 도전 체크 표시
- 오시는 길: 네이버 지도·카카오맵 길찾기 버튼, 대중교통과 주차 안내
- 처음 오는 가정을 위한 안내 문구
5단계 주의사항
  • 지도 링크는 눌러서 실제 위치로 연결되는지 꼭 확인합니다.
STEP 7-6

배포 · 인터넷에 공개하기

6단계 프롬프트
이 홈페이지를 무료로 인터넷에 공개하는 가장 쉬운 방법을 알려줘.
필요한 파일과 순서를 한 단계씩 설명해줘.
터미널 명령이 필요하면 내가 승인할 수 있게 준비해줘.
내 컴퓨터

나만 보고 고치는 단계

GitHub

코드를 보관하는 곳. 아이들 정보 저장소가 아닙니다.

Vercel · Netlify

인터넷에 공개하는 곳 → 공개 주소

터미널 명령을 직접 칠 필요는 없습니다. 에이전트에게 “GitHub에 올려 줘”라고 하면 준비하고 승인 버튼을 띄웁니다. git이 부담스러우면 완성된 폴더를 Netlify Drop에 끌어다 놓는 방법도 있습니다. 전용 도메인은 다음으로 미룹니다.

좋은 지시 공식

누구를 위해 + 무엇을 + 어떤 느낌으로 + 하지 말 것
예시
초등 1~3학년 아이들이 폰으로 보는 페이지야.
큰 글씨와 밝은 색으로, 오늘 말씀 퀴즈 3문제를 만들어 줘.
실명이나 연락처는 넣지 마.

에이전트가 막힐 때 · 오류 메시지를 그대로 복사해서 주고, “왜 안 되는지 쉽게 설명하고 고쳐 줘”라고 말하세요. 한 번에 큰 요청보다 작게 나눠서 요청합니다.

이것은 ‘프로토타입’입니다 · 공개 전 점검
  • 개인정보 처리와 아이들 사진 동의
  • 교회(담임목사·부서 담당 교역자) 승인
  • 이미지·음악 저작권 확인, 영상은 교회 공식 채널 것만
  • 누가 계속 업데이트할지 운영 계획

STEP 8 · 실습

홈페이지 수정하기

수정은 ‘말로’ 합니다. 코드를 몰라도, 눈에 보이는 것을 기준으로 요청하세요.

하고 싶은 일말하는 법
글자 키우기“본문 글자를 지금보다 크게 해 줘.”
색 바꾸기“제목 색을 하늘색 계열로 바꿔 줘.”
순서 바꾸기“사진 갤러리를 일정 위로 올려 줘.”
내용 고치기“소개 문장에서 ‘~합니다’를 ‘~해요’ 체로 바꿔 줘.”
폰 화면“휴대폰 화면에서 버튼이 너무 작아. 고쳐 줘.”
오류“퀴즈 버튼을 눌러도 반응이 없어. 원인을 찾아 고쳐 줘.”
